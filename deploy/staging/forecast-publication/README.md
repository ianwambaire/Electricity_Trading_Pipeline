## Architecture and boundaries

An optional staging-only `POWERFLOW_FORECAST_PUBLICATION_ROOT=/srv/powerflow/forecast-publications` selects an independent overlay for GET `/forecast/next24`. `/srv/powerflow/published` and every historical dataset/database remain untouched. Without this setting, existing API behavior is preserved. With it, missing/invalid/expired publications return503 with only `detail.code=FORECAST_WITHHELD`; there is NO fallback to historical forecast files. Responses use Cache-Control:no-store.

Each release is a single, bounded, strictly allowlisted `bundle.json`, stored at `releases/<SHA256>/bundle.json`. An atomic `current` symlink points to one immutable release. API reads resolve the pointer once and validate content hash, contract and three-hour freshness on EVERY request. Nothing is inferred or generated by the API. No administrative write endpoint is added. Only the separately approved root-operated CLI can publish. Candidate UID/GID992 has read access, never write access.

The bundle contains24 predictions, the approved model identity/hashes, issue/issuance/provenance, completed-run identity and minimal market/feature evidence. All31 features must be finite and match the approved schema. Exact price lags1/24/168, load lags1/24 and contiguous24-hour rolling windows are checked against supplied finite hourly histories. Complete four-quarter generation evidence, biomass, calendar fields, renewable aggregates, issue-hour operational weather provenance and execution chronology are checked. No environment files, credentials, private database, model binary, logs or unrelated artifact is accepted. The public API returns ONLY forecast rows and safe publication timestamps/status; it does not expose input vectors or Prefect run IDs.

**Evidence prerequisite:** The existing production CSV/provenance do not persist the full original31-feature input vector. This implementation deliberately does not fabricate that vector, substitute archive weather or claim a current re-fetch reproduces original operational weather. Before a real bundle can be built, separately approve trustworthy input-evidence collection/capture tied to a successful run. The evidence JSON must contain exactly `execution` and `inputs` as exercised in the synthetic test fixture. A successful task label alone is not a replacement for missing evidence. Filesystem hashes prove integrity, not provider authenticity; an approved operator must verify the actual sources before approving their hashes.

React validates publication metadata, displays “Valid published forecast” independently of the frozen pipeline's old WITHHELD state, shows remaining future targets, and masks charts/statistics/downloads when expiry is reached—even before another API poll. Expired/malformed overlay responses show WITHHELD. Other panels intentionally retain historical market/operational/evaluation sources.24 issue-relative horizons are NOT represented as24 still-future hours.
