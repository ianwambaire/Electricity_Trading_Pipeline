# Isolated staging API runtime proposal — not installed

Use the existing systemd/loopback approach; do not reuse the broad Docker Compose stack or modify the original EC2 unit in this phase. This template is for a separately approved Linux staging host. It needs an unprivileged `powerflow-api` service account, root-owned read-only release under `/opt/powerflow`, API-only venv, public configuration at `/etc/powerflow/react-api.env`, and a coherent read-only published snapshot rooted at `/srv/powerflow/published` (database, data and public artifact metadata). Creating users, directories/mounts, permissions, network access, proxy routes or services on AWS requires separate approval. No commands here have been executed remotely.

Build/release steps after approval:

1. Verify reviewed source revision, API lock and manifest; create a fresh `.venv-api` using Python3.14 and install `requirements/api.lock`. Run pip check and `scripts/check_api_runtime.py` with the approved API-only environment. First verify clean Linux x86_64 install: local clean testing used macOS, not EC2.
2. Populate the read-only snapshot through an approved process. Never run the production pipeline, initialize database schema or grant ingestion write credentials to stage the API. Verify schema read-only and classify absent data honestly.
3. Replace example hosts/client ID in api.env.example with reviewed public settings. Do not load the ingestion .env or Streamlit secrets. Invalid deployed identity/runtime settings abort startup; missing/incompatible DB stays not-ready. MFA enrollment is rejected in deployed modes.
4. Validate the unit and resource limits on staging before activation. One worker is intentional: bounded per-process market snapshots, JWKS cache and MFA coordination. MemoryMax512M/MemoryHigh384M/MemorySwapMax0/CPUQuota100%/32 concurrent tasks are initial guardrails, not measured capacity guarantees. OOM/restarts or latency require evidence/review, not automatic worker multiplication.
5. Bind loopback only. The application validates Host, but Uvicorn trusts forwarded headers only from loopback. The separately reviewed HTTPS proxy must preserve the approved Host and strip /api; do not trust arbitrary internet forwarding headers. Do not publish port8000 or modify production Nginx in this phase. Explicit CORS is optional, never wildcard.
6. Liveness `/health` indicates process service only. `/ready` requires identity configuration plus required operational schema readable within a short timeout, cached5s. It does not contact Cognito/JWKS, assert recent observations or guarantee forecast availability. Monitor product freshness separately. `/docs`, `/redoc`, `/openapi.json` are disabled in deployed modes.
7. Keep raw Uvicorn access logging disabled; application JSON telemetry includes random server-generated request IDs, route templates, status/duration, fixed lifecycle/failure events and401/403 outcomes. Never log raw URLs/query strings, Authorization, user IDs, body, exception text or provider payloads. Restrict/rotate journald and any proxy logs separately. The app is not a complete log-retention service.

HTTP routes are local additions until separately approved proxy deployment. No new public AWS endpoint is created here. The existing public market contract is preserved; own-account writes remain authenticated, all seven restricted report routes remain Admin-only. A public route policy/rate-limit review is still necessary.

Rollback after an approved staging release: retain prior source+lock+venv and public config in versioned releases, drain/stop within graceful timeouts, switch the reviewed release pointer, restart only with approval and verify health/readiness/auth. Do not restore older data, alter Cognito, weaken token validation or reset Git history to recover a service. There is no database migration in this phase. In-memory setup state never survives a restart; status must be refreshed rather than assuming success.

This template does not grant filesystem permissions or prevent every instance-role credential path. Stage with no production write role, review IMDS/network isolation, and verify effective permissions. Streamlit, Prefect, MLflow, DNS and production services remain unchanged.
