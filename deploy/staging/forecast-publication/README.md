## Architecture and boundaries

An optional staging-only `POWERFLOW_FORECAST_PUBLICATION_ROOT=/srv/powerflow/forecast-publications` selects an independent overlay for GET `/forecast/next24`. `/srv/powerflow/published` and every historical dataset/database remain untouched. Without this setting, existing API behavior is preserved. With it, missing/invalid/expired publications return503 with only `detail.code=FORECAST_WITHHELD`; there is NO fallback to historical forecast files. Responses use Cache-Control:no-store.

Each release is a single, bounded, strictly allowlisted `bundle.json`, stored at `releases/<SHA256>/bundle.json`. An atomic `current` symlink points to one immutable release. API reads resolve the pointer once and validate content hash, contract and three-hour freshness on EVERY request. Nothing is inferred or generated by the API. No administrative write endpoint is added. Only the separately approved root-operated CLI can publish. Candidate UID/GID992 has read access, never write access.

The bundle contains24 predictions, the approved model identity/hashes, issue/issuance/provenance, completed-run identity and minimal market/feature evidence. All31 features must be finite and match the approved schema. Exact price lags1/24/168, load lags1/24 and contiguous24-hour rolling windows are checked against supplied finite hourly histories. Raw price/load samples must cover every required history hour, including all four quarters where required, and reproduce the hourly means. Complete four-quarter generation evidence, biomass, calendar fields, renewable aggregates, issue-hour operational weather provenance and execution chronology are checked. No environment files, credentials, private database, model binary, logs or unrelated artifact is accepted. The public API returns ONLY forecast rows and safe publication timestamps/status; it does not expose input vectors or Prefect run IDs.

**Authentic evidence capture is now implemented locally, not deployed.** The old production CSV/provenance still cannot supply retrospective evidence. `run_next24h_forecast()` now captures the exact ordered dataframe immediately before `model.predict()`; it never re-fetches weather or reconstructs a historical input vector. Raw market source bytes are captured once and used by both existing cleaners and evidence extraction. A successful task label alone is not a replacement for a matching receipt. Filesystem hashes prove integrity, not provider authenticity or protection against a privileged actor who can rewrite the entire set; independently approve source receipts and their hashes.

React validates publication metadata, displays “Valid published forecast” independently of the frozen pipeline's old WITHHELD state, shows remaining future targets, and masks charts/statistics/downloads when expiry is reached—even before another API poll. Expired/malformed overlay responses show WITHHELD. Other panels intentionally retain historical market/operational/evaluation sources.24 issue-relative horizons are NOT represented as24 still-future hours.

## Authentic inference receipt schema v1 (local implementation, 2026-10-31)

The production code changes are `src/models/next24h.py`, `src/models/next24h_production.py` and new `src/models/inference_evidence.py`. No model, feature calculation, freshness threshold, schedule or historical file schema changes. Capture is an optional callback in the shared prediction helper; only operational inference supplies it. The copied matrix preserves the original 31-column order and numerical values passed to predict, before a model could mutate its argument. Predictions still use the original dataframe and original model call.

Default new private output: `data/reports/next24h_inference/<inference-UUID>/`, relative to the existing inference working directory. An explicit `evidence_root` Python argument is available for isolated tests or a separately reviewed installation. This is a NEW production write path requiring approval before deployment. Do not add it to any automatic S3 sync or public API. The UUID identifies the inference invocation, not a Prefect flow/task ID. An immutable receipt means inference generated a result; it does not assert the enclosing Prefect run completed. Independently verify the scheduled task/run result before approving a real publication.

Every completed directory contains:

| File | Contents and binding |
| --- | --- |
| `forecast.csv` | Exact serialized 24-row inference output; unchanged legacy CSV schema. |
| `provenance.json` | Original weather provenance plus `inference_evidence`: schema version, inference UUID and SHA-256 of the canonical evidence payload excluding its `artifacts` member. This archived copy alone has the new binding; the legacy provenance remains unchanged. |
| `model.json` | Allowlisted public release ID, model/contract hashes, ordered features, count and horizons. Internal candidate paths and unrelated model metadata are excluded. |
| `evidence.json` | Version 1; execution timestamps/UUID; inputs (all 31 actual values, exact required hourly histories, original price/load samples and generation quarters); inference (ordered feature names/values, issue/targets, model identity, three raw-source hashes, hash of original verified release manifest); artifact hashes for forecast, archived provenance and public model metadata. |
| `integrity.json` | Version, inference UUID and SHA-256/size-independent integrity map of the preceding four exact files. Approve these hashes independently for the existing four-input builder. |

Canonical payload hashing uses UTF-8 JSON, sorted keys, compact separators and rejects nonfinite values. Source hashes identify only the byte snapshots used in this invocation; source CSVs/databases are NOT copied into receipts. Market samples are restricted to the exact hours/fields required by the contract. Weather evidence is the five real values in the captured matrix and the existing operational acquisition provenance, not a later provider query. No credentials, tokens, environment settings, model binaries, private database rows or raw logs are captured.

The root and temporary/completed directories are private 0700; files are 0600. Existing broader-permission roots fail closed. All five files are written and fsynced inside a unique `.partial-*` directory, then the entire directory is renamed atomically to its UUID and the parent is fsynced. There is no mutable latest pointer. Do not select partial directories, and do not collect individual legacy latest files for publication. A failed commit retains partial artifacts; there is no automatic deletion/retry or fallback. Receipts are committed before the unchanged legacy save path: a capture failure aborts without altering legacy reports; a later legacy save failure can leave a complete inference receipt, which is not evidence of overall task success. Receipts from unchanged/repeated issues remain distinct invocations; they cannot overwrite one another.

`prepare.py` requires all four files from ONE completed receipt and their independently approved hashes. It verifies reciprocal provenance/evidence binding, the ordered matrix against feature values, source/model hash syntax, issue/target agreement, then the existing full input-completeness/model/freshness validator. Unversioned old evidence is now rejected. Different-run evidence/provenance, missing files, reordered features, changed predictions and expired receipts are rejected. The final publication bundle stays schema v1 and the API's per-read expiry rule is unchanged.
