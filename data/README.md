# PowerFlow data directory

This directory contains PowerFlow's source extracts, transformed datasets, model inputs, reports, and backups. Most contents are generated or downloaded and are intentionally excluded from Git.

## Directory layout

### `raw/`

Direct inputs for the primary pipeline:

- `raw/entsoe/prices.csv`
- `raw/entsoe/load.csv`
- `raw/entsoe/generation.csv`
- `raw/weather/open_meteo_weather.csv`

The ENTSO-E files contain Germany-Luxembourg market data. The weather file contains observations at the Berlin coordinates. Historical mode shares an inclusive UTC range, defaulting to `2019-01-01` through `2025-09-30`, while incremental mode starts each source immediately after its own stored watermark. Appends are chronological, duplicate-free, atomic, and reject conflicting overlap. Open-Meteo timestamps are requested explicitly in UTC and use a conservative five-day archive publication delay. Since ENTSO-E day-ahead prices became quarter-hourly on `2025-10-01`, the Silver builder averages four complete quarter-hours into each UTC hour. These files are generated by the ingestion scripts and are not committed.

The root-level `raw/electricity_market_data.csv` belongs to the retained legacy EIA pipeline.

### `external/`

Downloaded EIA and Open-Meteo files used by the retained legacy California pipeline. These are generated external inputs and are not part of the primary ENTSO-E flow.

### `processed/`

Cleaned and aligned datasets. The primary output is:

- `silver_electricity_market_data.csv`

The silver dataset joins hourly price, load, generation, and weather data by timestamp. Incremental runs currently rebuild this file from the complete raw history; this is intentional so UTC continuity and hourly aggregation are rechecked before Gold generation. `clean_electricity_market_data.csv` is a legacy pipeline output.

### `features/`

Model-ready feature tables. The primary output is:

- `gold_model_features.csv`

It contains calendar features, lags, rolling statistics, renewable-generation measures, and the next-hour price target. Incremental runs rebuild Gold from the complete Silver history so all 31 frozen-model features remain continuous at the update boundary.

The trainer computes a SHA-256 hash of the exact gold CSV bytes. The resulting
identifier, `gold-sha256-<digest>`, is stored in the generated model manifest.
This identifies the model input precisely without duplicating the dataset.

### `final/`

Final combined datasets from the retained legacy EIA/Open-Meteo pipeline. This directory is generated and is not used by the current dashboard.

### `reports/`

Generated analysis and model outputs, including:

- model-comparison CSVs;
- actual-versus-predicted CSV and PNG outputs;
- anomaly CSV and PNG outputs;
- feature-importance CSV and PNG outputs;
- expanding-window backtest comparison and aggregate CSVs;
- feature-ablation, market-regime, and yearly price-distribution CSVs;
- focused model-tuning, regime, and linear-coefficient diagnostic CSVs;
- one-time final-holdout metrics, baseline, and regime CSVs; and
- validation reports.

These reports can be regenerated and are excluded from Git.

### `backups/`

Timestamped snapshots created by legacy API-ingestion scripts. They are local backup data, not source-controlled assets.

### `sample/`

Small, intentionally committed examples for repository review and development documentation. Samples must:

- remain small;
- contain no credentials or sensitive information;
- clearly identify their source schema;
- never replace production inputs; and
- never be referenced by the production pipeline unless that behavior is explicitly designed later.

`sample/entsoe_silver_sample.csv` is a 150-row schema sample copied from the existing silver dataset. It represents consecutive historical hourly records and is not intended to reproduce full-dataset distributions or model results.

## Generation and Git policy

The primary flow generates data in this order:

```text
raw/ → processed/silver_electricity_market_data.csv
     → features/gold_model_features.csv
     → reports/
```

Active raw, silver, gold, final, report, external, and backup outputs are excluded through `.gitignore`. Only small, deliberately reviewed files under `data/sample/` should eventually be committed.

## Archive policy

- **GitHub:** documentation and small representative sample data only.
- **Local storage:** active pipeline inputs and outputs used during development.
- **Google Drive:** archived large source datasets, dated dataset snapshots, and final dataset backups that need to be retained or shared.

No automated Google Drive upload is implemented. Archiving is currently a manual project-management decision.

Recommended Drive locations are `PowerFlow/datasets/snapshots/` for reviewed
gold snapshots and `PowerFlow/datasets/archives/` for older large exports. See
[`docs/google_drive_workflow.md`](../docs/google_drive_workflow.md).
